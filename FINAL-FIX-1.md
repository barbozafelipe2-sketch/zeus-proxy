# Final Fix 1/3 — Product integrity and lifecycle

This pass closes the first group of findings from the final OlyHub audit plus the external Zeus/Olympus review.

## Scope fixed

- Project workspace hydration is now centralized. Project conversations opened from history reload Tasks, approved Memory, Files and Artifacts before the workspace is shown.
- Global Files/Tools surfaces explicitly reload global output scope; returning to an active Project reloads Project scope.
- Files and Artifacts now support owned deletion. Database rows are deleted only for the authenticated owner, the Blob key is queued in the existing durable GC queue, and cleanup is attempted immediately.
- Project deletion is exposed in the Edit Project modal and uses the existing transactional project cascade + Blob queue behavior.
- Synchronous artifact generation now has explicit per-format character/line budgets and a 12 MB generated byte ceiling. This protects PPTX/XLSX/PDF/DOCX generation from pathological payloads.
- The Documents Tool is READY only when chat/AI is actually available.
- XLSX extraction now uses ExcelJS, which was already a dependency for XLSX generation. The separate `xlsx` dependency was removed. Legacy `.xls` is reported as unsupported and users are asked to convert to `.xlsx` or `.csv`.

## Preserved invariants

No database migration was added. Canonical Project chat, request idempotency, transactional chat finalization, secret scrubbing, archive safety, rate/concurrency controls, provider fallback/circuit breaker, and the 4.3.0 premium UI remain in place.

## Deferred to Final Fix 2/3 and 3/3

Zeus/Olympus orchestration tuning, memory policy, download error contracts, auth/session hardening, automatic GC maintenance, PDF Unicode/layout, task lifecycle UX, accessibility/dialog polish, and final deployment reproducibility remain intentionally outside this pass.

## Reproducible-install note

A `package-lock.json` was attempted with `npm install --package-lock-only --ignore-scripts --no-audit --no-fund`, but the registry operation timed out in the build environment. No partial lockfile or `node_modules` directory was kept. Lockfile generation remains a deployment-reproducibility item for a later fix pass or a connected CI environment with registry access.
